# Kubernetes migration candidates

- [Kubernetes guestbook](https://github.com/kubernetes/examples/tree/master/guestbook): frontend and Redis Deployment+Service pair; exercises a multi-workload application and service discovery; expected verdict is partial until native service DNS/network policy exists.
- [Canonical CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/): scheduled finite work with completion and concurrency policy; exercises the `APP schedule`/timer mapping; expected verdict is a faithful timer-shaped conversion with job-policy losses recorded.
- [prometheus-node-exporter DaemonSet](https://raw.githubusercontent.com/prometheus-community/helm-charts/main/charts/prometheus-node-exporter/templates/daemonset.yaml): one host observer per node with `/proc` and `/sys` visibility; exercises declared read-only host surfaces; expected verdict is an honest refusal or partial mapping because automatic per-node reconciliation is absent.
- [ingress-nginx controller](https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/charts/ingress-nginx/templates/controller-deployment.yaml): API-watching ingress controller; exercises control-loop and cluster-edge boundaries; expected verdict is refusal/partial because composix has host binds, not Kubernetes API reconciliation.
- [Bitnami PostgreSQL StatefulSet](https://raw.githubusercontent.com/bitnami/charts/main/bitnami/postgresql/templates/primary/statefulset.yaml): durable singleton database with stable identity and state; exercises the `STATEDIR` mapping; expected verdict is partial because stable pod identity and cluster service discovery are unbuilt.
- [minimal nginx Deployment](https://raw.githubusercontent.com/kubernetes/website/main/content/en/examples/application/deployment.yaml): replicated stateless HTTP workload; exercises Deployment/replica semantics; expected verdict is partial because one path-keyed instance exists but replica reconciliation does not.
