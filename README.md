# composix

`cix` — a docker-shaped toolkit on nix + systemd.

Docker got the *workflow* right: name a build, publicize `our-app:v321`, run it anywhere,
compose services into applications. But it reinvented the machinery underneath — image formats,
layer stores, a daemon, a second init system. That machinery already exists, better: **nix**
has content-addressed, reproducible artifacts with a real closure model, and **systemd** has a
hardened, capable service runtime. composix is the thin layer that gives that stack docker's
ergonomics.

**Status: early and moving fast.** Three of the four parts work end-to-end; compose is being
built now. Everything may change.

## The four parts

| part | what | status |
| --- | --- | --- |
| **index** | `cix tag` / `serve` / `pull` — mutable names over immutable store paths; the ref is literally a URL | working |
| **spec + run** | `cix-spec.json`, a capability contract compiled to hardened systemd units; `cix run` | working (spec v3) |
| **Cixfile** | dockerfile-shaped authoring without writing nix; `cix build` with a lockfile | working (v1: assembly) |
| **compose** | `compose.json` composites: tracked tags, unix-socket edges, atomic rollback via nix profiles | in progress |

## A taste

```dockerfile
# Cixfile — this is examples/nginx, verbatim
PKG nginx

COPY index.html /srv/www/index.html

LINK bin/nginx ${nginx}/bin/nginx
LINK /etc/nginx/mime.types ${nginx}/conf/mime.types

COPY nginx.conf /etc/nginx/nginx.conf

SERVICE nginx
EXEC bin/nginx -c /etc/nginx/nginx.conf -e stderr
PORT http = 8080
CACHE /var/cache/nginx
RUNDIR /run/nginx
```

```sh
cix build examples/nginx -t my-nginx:v1   # deterministic: nixpkgs pinned in Cixfile.lock
cix run my-nginx:v1                       # a hardened transient systemd unit

# on the box your org's DNS calls cix.my-org.com:
cix serve --with-store                    # serve your tags + a binary cache

# anywhere else:
cix pull cix.my-org.com/my-nginx:v1
```

The fully-qualified ref **is a URL**: paste `cix.my-org.com/my-nginx:v1` into a browser and
you get an informative page about exactly that artifact; the `cix` client requests the same
URL with `Accept: application/vnd.cix+json` and gets the machine representation. No default
registry exists or ever will: bare names are local, qualified names are remote, and
serving = exposing your tags at whatever URL reaches your box.

**Declaring is granting — and undeclared is denied, kernel-enforced.** No ports declared ⇒
`PrivateNetwork`. A declared port ⇒ exactly that bind allowed (`SocketBindAllow`), below
1024 ⇒ exactly that capability. A `listeners` service accepts an inherited fd and can create
no IP socket at all. State/cache/log/run dirs map to systemd's native managed directories at
the paths the app expects; the item itself is projected read-only at its native absolute
paths (`/etc/nginx/…`) — a sparse rootfs fragment, no layers, no templating.

## Examples

`examples/` is the seed of a spec'd-packages collection: nginx and postgres (each as both a
Cixfile and a `default.nix` escape hatch), a pure socket-activated service
(`examples/listenfds`), unix-socket-only variants proving the capability-style networking
tier (`examples/dstyle`), and a realistic rust-workspace + frontend build shape
(`examples/buildshape`). Each has a `demo.sh`; a NixOS VM check
(`nix build .#checks.x86_64-linux.vm-dogfood`) runs the core ones as root in a disposable VM.
