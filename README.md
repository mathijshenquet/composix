# composix

`cix` — a docker-shaped toolkit on nix + systemd.

Docker got the *workflow* right: name a build, publicize `our-app:v321`, run it anywhere,
compose services into applications. But it reinvented the machinery underneath — image formats,
layer stores, a daemon, a second init system. That machinery already exists, better: **nix**
has content-addressed, reproducible artifacts with a real closure model, and **systemd** has a
hardened, capable service runtime. composix is the thin layer that gives that stack docker's
ergonomics.

**Status: early and moving fast.** The index and runner work end-to-end; compose and the
Cixfile are designed but not built. Everything may change.

## The four parts

| part | what | status |
| --- | --- | --- |
| **index** | `cix tag` / `serve` / `pull` — mutable names over immutable store paths | working |
| **spec + run** | `cix-spec.json`, a capability contract compiled to hardened systemd units; `cix run` | working |
| **compose** | tracking compose files: services update when tags move, atomic per-composite rollback | designed |
| **Cixfile** | dockerfile-like authoring without writing nix | designed |

## A taste

```sh
cix tag .#my-app my-app:v1        # name a build (the tag is a nix GC root)
cix run my-app:v1                 # run it as a hardened transient systemd unit

# on the box your org's DNS calls cix.my-org.com:
cix serve --with-store            # serve your tags + a binary cache

# anywhere else:
cix pull cix.my-org.com/my-app:v1
```

The fully-qualified ref **is a URL**: paste `cix.my-org.com/my-app:v1` into a browser and you
get an informative page about exactly that artifact; the `cix` client requests the same URL
with `Accept: application/vnd.cix+json` and gets the machine representation. No default
registry exists or ever will: bare names are local, qualified names are remote, and
serving = exposing your tags at whatever URL reaches your box.

Everything undeclared is denied at runtime: a service that doesn't declare a port gets
`PrivateNetwork`, undeclared paths are read-only or invisible, state/cache/log dirs map to
systemd's native `StateDirectory`/`CacheDirectory`/`LogsDirectory` with bind mounts onto the
paths the app expects.
