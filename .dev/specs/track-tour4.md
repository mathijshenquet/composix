## Editorial rules (binding)

1. **Dual audience**: every Docker analogy gets a self-standing
   explanation in Nix/systemd/file terms in the same breath. Analogies
   are additive, never load-bearing (reader B failed on every bare
   analogy; reader A on every bare Nix term).
2. **Define-at-first-use**: item, index, binder, artifact, projection,
   role directory, rootless/degraded path, family, memo, lock, closure —
   one plain sentence at first use, no forward references. The preamble
   phrase "isolated local index" confused both readers seven times:
   reword the generated preamble (verbatim below).
3. **Every command typeable**: no ellipsized store paths in commands.
   Teach the capture idiom once in chapter 1 —
   `item=$(cix build .#hello)` style — and use `$item` everywhere
   after. Display-only ellipsis stays in OUTPUT only; chapter 1 says so
   once.
4. **The promised service RUNS**: chapter 1 ends with a real rootless
   `cix run --user` + HTTP probe + stop, and chapter 5 runs its web
   service. Determinism vs host-varying degradation warnings: the
   harness NORMALIZES the warning block to one fixed marker line
   `[manager degradation warnings vary by host — elided]`, with one
   prose sentence saying exactly that. Honest (nothing fabricated,
   elision declared) and deterministic. This supersedes the
   tourfix-era non-executed-prose choice for these two demos ONLY where
   the command works under both CI's and dev's user managers — the CI
   manager rejects PrivatePIDs and drops the whole property set, so
   verify the rootless run itself still starts there (the harness's

> play the role of images, units of containers, the Cixfile of the
