## Executive judgment

The workspace has no Cargo cycle, and the earlier thinning did real work:
`cix-index` is small and cleanly split; `cix-compose` has an accurate ownership
map and its live production conductors are below 1,050 LOC. The structural
discipline is nevertheless losing ground in three places:

1. The CIP-89 exception has grown from 3,492 to 4,369 physical LOC and still
   contains six live strata plus 254 lines of commented extraction debris.
2. D67/D73 say manifest/runner, Cixfile language, build engine, and index are
   separate strata, but the crate graph and source ownership do not match that
   decision: `cix-build` still owns 1,515 LOC of language codegen and a second
   manifest model, while low-level runner/build crates resolve index names.
3. `cix-run/src/runtime.rs` is at 1,969/2,000 LOC with several host-lifecycle
   strata and a superseded `ps` implementation still in the file.

The next thinning round should address those three before adding another build,
runtime, or contract feature. The remaining findings are smaller but concrete:
test/doc-generation code has become a second set of monoliths; alpha-only
accepted surfaces outlived their evidence; and the module-map/shared-state rules
are review conventions rather than enforced invariants.

### Crate dependency direction

The graph is acyclic. `cix-common` is the leaf; `cix-index` depends only on it;
`cix-compose` correctly consumes `cix-run` and `cix-index`; the `cix` binary is
the expected top-level aggregator. Three cross-stratum edges carry orchestration
downward:

- `cix-run -> cix-index`: one block in `runtime.rs` opens the index and resolves
  names before falling back to Nix. D67's manifest/runner stratum therefore
  cannot be used independently of distribution even though the schema is
  explicitly meant to be index-independent.
- `cix-build -> cix-index`: `lock.rs::ensure_lock` accepts a concrete
  `cix_index::Store` solely to resolve artifact `FROM` references. Its internal
  `ensure_lock_with` already demonstrates the narrow resolver callback seam.
- `cix-cixfile -> cix-compose`: all use is in `watch.rs`, where a language/build
  crate parses a compose tree, retags outputs, and activates it. This makes any
  Cixfile consumer compile the compose/systemd stack and puts dev-loop
  orchestration below the binary boundary.

These edges do not create a cycle today, but they force the conceptual order
`index -> run -> compose -> cixfile` and prevent the D67 strata from remaining
independent libraries. The disabled `codegen.rs` tests make the pressure
visible: they import `cix-cixfile::parse` from `cix-build`, which would complete
a Cargo cycle, so the entire test module is compiled under
`#[cfg(all(test, any()))]` and can never run.

## Prioritized findings

### P0. Finish the grandfathered build-chain split with owned interfaces — L

**Evidence.** `build_chain.rs` is 4,369 LOC, 2.18× the normal limit and 877 LOC
larger than the 3,492-LOC CIP-89 measurement. Lines 159–412 are a 254-line block
comment containing the already-extracted `fetch.rs` implementation. The inline
test module occupies 773 lines. After excluding both, approximately 3,342 live
production lines remain. They divide as follows:

| range | live stratum | extraction cost |
| --- | --- | --- |
| 414–1,339 | top-level FETCH and BUILDER step execution (266- and 601-line functions) | M; keep ordering in conductor, move per-step executors behind result structs |
| 1,340–1,805 | environment filtering, consumed-path analysis, chain/memo keys | M; key inputs are already explicit request structs |
| 1,806–2,425 | memo validation, constructive replay, read/write-set reduction | L; narrow boundary must own memo validation and snapshot application together |
| 2,438–2,880 | workspace state, FETCH snapshots, volatility, staging and tree reconciliation | M; natural `Workspace` owner with state/sync/snapshot methods |
| 2,881–3,126 | Nix context evaluation, cache, offer realization, closure query | M; explicit context resolver service |
| 3,127–3,469 | sandbox command assembly, import union, FHS/network fallback | M; compose existing `seccomp`/`fhs` modules through a sandbox request/result |
| 3,470–3,596 | NAR hashing and FETCH-pin refresh/verification | S–M; belongs with FETCH snapshot state, not the conductor |

The old thinning log stopped because memo/workspace code depended mutually on
conductor-local helpers. That was the right refusal then, but the current file
now exposes the missing interface: memo replay and workspace reconciliation
must move together or communicate through an owned `Workspace`; splitting by
function families alone would repeat the coupling.

**Concrete harm.** Four of ten recent merges still edited this exception.
Unrelated FETCH, scratch, cache, and copy work shares one conflict domain; the
601-line `execute_builder` must understand credentials, trace capture, memo
replay, workspace sync, sandbox fallbacks, and pin refresh. Any one of those
changes can invalidate tests 3,600 lines away, and the source-size exception
provides no remaining growth brake.

**Proposed decomposition.** Execute the accepted CIP-89 intent as four
behavior-preserving legs: remove extraction residue and move tests; introduce
`Workspace`; introduce `MemoEngine` owning validation plus constructive replay;
move Nix context/sandbox and FETCH snapshot/pin services. Leave only ordering
and typed requests/results in `build_chain`. Exact proposal:
[build-chain-seams.md](../cips/draft/build-chain-seams.md).

### P0. Make the D67/D73 crate graph tell the truth — L

**Evidence.** D73 says the build engine is chain/key/workspace/sandbox while
parser/codegen are language. In reality `cix-build` owns `model.rs` (445 LOC),
`eval_plan.rs` (323), and `codegen.rs` (1,515), and `cix-cixfile` re-exports
them. `cix-build::model` and `cix-run::spec` independently define ten matching
contract concepts (`Service`, `Secret`, `Claim`, `Readiness`, `Liveness`,
`Probe`, `Env`, `Port`, `Protocol`, `Dirs`). `codegen.rs` then hand-emits the
runtime manifest twice: Nix syntax and literal JSON; the duplicated manifest
section alone is 654 lines (681–1,334). Its 148-line test module is permanently
disabled to avoid the reverse `cix-build -> cix-cixfile` test dependency.

The stop-disposition track is a representative cost: one contract field changed
11 Rust files spanning build model/codegen, parser/formatter/diagnostics,
compose model/generation, and run spec/unit. Separately, index resolution lives
inside both `cix-run` and `cix-build`, and compose activation lives inside
`cix-cixfile::watch`.

**Concrete harm.** A manifest field can compile in one representation and be
missing from the other; the most direct cross-check is disabled. Low-level
libraries cannot be tested or reused at their stated seams without pulling in
upper product strata. Every contract addition fans out across duplicate types,
serializers, and crate boundaries before its actual behavior is implemented.

**Proposed decomposition.** Put the single alpha manifest schema and canonical
serialization in a neutral stratum-1a crate/module consumed by run, compose, and
the SERVICE/APP adapter. Make `cix-cixfile` a language front end rather than a
build/compose orchestrator; move build/watch CLI coordination to the binary or a
top-level application crate. Inject name resolvers into run/build library APIs;
keep concrete index access at orchestration boundaries. Split parser directives
by D67 ownership (`inputs`, `builder`, `assembly`, `contract`) while retaining
one parser state and declarative diagnostics. Exact proposal:
[crate-strata.md](../cips/draft/crate-strata.md).

### P1. Thin `cix-run::runtime` before the next runtime feature — M

**Evidence.** `runtime.rs` is 1,969 LOC, leaving 31 lines before the hard fail;
1,841 lines precede its test module. It owns at least five separable concerns:
run-directory overrides (108–331), finite/scheduled app execution (332–548),
service start/degradation policy (549–832), listener/unit/GC-root lifecycle
(833–1,309), foreground journal/systemd control (1,310–1,534), and
index/Nix target resolution (1,535–1,717). Lines 1,728–1,841 implement an old
human-only `ps`; the actual binary intercepts the `Ps` command in `main.rs` and
calls `cix_compose::ps(json)`, so this second renderer/list-units path is not
reachable from `cix`.

`unit.rs` is also at 1,929 LOC, but only 913 are live; 1,016 are an inline
fixture/test module. The run module map does not mention `runtime` at all.

**Concrete harm.** One small feature will trip CI without identifying the
correct boundary, encouraging a threshold exception or arbitrary move. Runtime
fallback, persistent-unit lifecycle, transient execution, target resolution,
and observability currently share imports and private helpers, so manager
behavior changes conflict even when they affect different user stories. The
dead `ps` path can silently diverge from the public JSON/table implementation.

**Proposed decomposition.** Remove the superseded `ps` surface after API
confirmation; extract target resolution, app/schedule execution, and persistent
manager/listener lifecycle; leave `runtime.rs` as the run/start conductor.
Move `unit` fixtures/tests to a submodule so the source tripwire measures the
compiler rather than golden volume. Exact proposal:
[runtime-thinning.md](../cips/draft/runtime-thinning.md).

### P1. Turn tour/corpus generation into maintained tooling — M

**Evidence.** Test-only code totals 15,376 LOC. The two doc generators account
for 3,945 LOC: `tour.rs` is 2,739 lines and `corpus.rs` is 1,206. `tour.rs`
combines process cleanup, command execution, normalization, fixtures, seven
134–374-line chapter programs, Markdown rendering, destructive generation,
drift checks, and six tests. A normal test run calls `render_tour` four times
(twice for determinism, once for foreign-unit isolation, once for drift), and a
global mutex serializes complete renders because they share a fixed listener.
It was the largest recent Rust churn surface at +1,144/-383 across four merges.

`corpus.rs` combines corpus discovery/ledger parsing with approximately 390
lines of hand-written Cixfile/Dockerfile/Nix/JSON/YAML highlighting and HTML
generation. Normal tests render the full browser three times. Both ignored
generators delete their complete output directory before writing; prior project
logs record a failed tour run leaving committed pages deleted. Generated
`docs/corpus/index.html` changed in seven of ten recent merges. General test
support is also repeated: `add_to_store`, `find_program`, and
`command_succeeds` each have three definitions; six system/user health fixture
pairs are byte-identical (12 of 34 fixture files).

**Concrete harm.** Documentation editing requires understanding systemd/Nix
cleanup and page rendering in a source-size-exempt integration test. Ordinary
workspace tests repeat expensive end-to-end generation, increasing gate time
and host-global flake exposure. Generator failures mutate tracked output before
a complete replacement exists, and broad generated diffs create frequent merge
conflicts unrelated to implementation logic.

**Proposed decomposition.** Create a reusable doc-generation support module or
tool with atomic directory replacement and one shared generated-file/drift
contract; split each tour chapter into its own scenario module; make isolation
tests inject roster/normalization inputs instead of rerendering all chapters;
separate corpus loading, highlighting, and page templates. Add a small shared
integration-test support module for Nix/store/process helpers and generate
system/user-identical fixture expectations from one source. Exact proposal:
[doc-harness-thinning.md](../cips/draft/doc-harness-thinning.md).

- Eighteen whole-tree `FetchPin` records remain across nine committed locks.
  They are current persisted evidence and must remain until those locks are

**Concrete harm.** Legacy fields expand every lock constructor, validator, and

### P2. Make structural guardrails complete and auditable — S

**Evidence.** Only compose has a complete crate-root map. The size script does
not verify that a map exists or mentions each direct module, so build/run maps
drifted immediately after new `scratch` and runtime work. It also counts inline
tests: `unit.rs` is presented as a 1,929-LOC implementation although its live
compiler is 913 LOC.

The shared-state inventory found 12 ownership/static declaration sites and no
`Rc` or `RwLock`. Seven have a site-local justification that holds:

- the two `cix-common` atomics (instrumentation and signal communication);
- the build timing `OnceLock`;
- scratch `KEEP_SCRATCH` and `LIVE` registry;
- Cixfile watch's process-global Ctrl-C handler `Once`;
- the tour render mutex guarding the fixed host listener.

Five sites have a valid technical rationale but violate the required comment
rule: scratch `SIGNAL_CLEANUP: Once`; tour `NEXT_TOUR_PORT: AtomicU16`; the
index atomicity test's `Arc<AtomicBool>`; and two compose resolver-test
`RefCell<Vec<_>>` call logs. The latter are idiomatic because the injected
resolver is `Fn`, not `FnMut`; that rationale simply is not stated. No site was
found whose underlying sharing was unjustified.

**Concrete harm.** Reviewers cannot trust the map as the pointer named by the
2,000-line error, and a mechanical green size gate can be triggered by golden
tests rather than production coupling. The shared-state rule currently depends
on remembering a manual grep; compliant and noncompliant sites look identical
to CI.

**Proposed decomposition/guardrail.** Require an exhaustive direct-module map
for multi-module crates and check names mechanically; report production and
inline-test LOC separately while retaining a total-file ceiling; add the
shared-state grep to the audit checklist and make each exceptional declaration
carry a preceding rationale. Exact proposal:
[structural-guardrails.md](../cips/draft/structural-guardrails.md).

### P2. Parser directives are the next language hotspot — M

**Evidence.** `parser/directives.rs` is 1,474 LOC, is one giant `impl Parser`,
and changed in three of ten recent merges (+109/-28); its 951-line integration
test changed in four. The parser submodule split successfully moved machine,
validation, diagnostics, and migrations out, but all input, builder, assembly,
and runtime-contract directives still share one file. `cix-cixfile` has no
module map to tell new grammar work where it belongs.

**Concrete harm.** A syntax track adding one runtime contract field conflicts
with build/FETCH grammar and formatter work in the same implementation and test
files. At the current growth rate two similar tracks bring the file near the
tripwire, where a hurried mechanical split would be riskier.

**Proposed decomposition.** Split extension `impl Parser` blocks along the D67
seams—inputs, builders, artifact assembly, and manifest contract—while keeping
`Parser` state and common validation centralized. Split parser integration
tests by the same ownership. This is included in the broader
[crate-strata.md](../cips/draft/crate-strata.md) proposal; it is independently
an M-sized pure move.

## What is healthy and should not be churned

- `cix-index`: 1,685 source LOC, no upward dependency, thin root, and domain
  modules with clear operations. Add `cli` to the map; no restructure is
  justified by this audit.
- `cix-compose`: prior thinning held. Live sizes are approximately 706 LOC
  model, 714 resolve, 945 generation, and 1,048 runtime; directory and network
  ownership is explicit and the module map matches reality. Large total file
  counts are mostly colocated tests. Avoid another split until a new owned type
  or repeated churn supplies evidence.
- `cix-common`: 225 LOC and both process-wide atomics are narrowly justified.
- Rejection-only migration diagnostics: they do not preserve behavior or data
  formats and are consistent with the alpha posture.

## Recommended order

1. Alpha prune of dead/commented/zero-exhibit surfaces (small, lowers noise).
2. `cix-run` runtime thinning before any new runtime feature crosses the cap.
3. Build-chain owned-interface legs under the existing quiet-crate/pure-move
   conditions of CIP-89.
4. Crate-strata/manifest ownership change; this is the largest semantic move
   and should follow the local thinning so its interfaces are visible.
5. Doc/test tooling and structural guardrails; these can proceed independently
   once no generator-heavy documentation track is in flight.

No implementation fix, test, formatter, or VM run was performed for this
findings-only track. The only required verification is `git diff --check` after
the report/drafts are complete.
